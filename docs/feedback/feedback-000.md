# 결과물 피드백

- 작성일: 2026-10-19
- 대상 결과물: 개인 이력서 웹사이트
- 관련 작업: Minimal Editorial · Portfolio UI System 적용
- 상태: 반영 완료

## 피드백

### 웹사이트 UI 디자인 가이드라인
**Minimal Editorial · Portfolio UI System**

버전: 1.0  
목적: 여백, 타이포그래피, 그리드, 이미지 중심의 미니멀한 웹사이트를 일관되게 설계하기 위한 실무 기준  
참고: 사용자가 제공한 UX/UI 디자이너 포트폴리오 링크 및 Readymag·Minimal Gallery 계열의 편집적 웹 디자인 분위기

> 이 문서는 참고 사이트의 원본 스타일을 픽셀 단위로 복제한 명세가 아니라, 유사한 시각적 방향을 구현하기 위한 독립적인 디자인 시스템이다. 실제 프로젝트의 브랜드와 콘텐츠에 맞춰 조정한다.

### 1. 디자인 방향

**핵심 키워드**
- Minimal: 불필요한 장식과 UI 요소를 줄인다.
- Editorial: 인쇄 편집물처럼 제목, 본문, 이미지의 위계를 명확히 한다.
- Whitespace-led: 여백을 빈 공간이 아니라 시선과 리듬을 조절하는 요소로 활용한다.
- Portfolio-first: 프로젝트와 이미지가 인터페이스보다 먼저 보이게 한다.
- Quiet interaction: 움직임은 짧고 목적이 분명해야 한다.

**디자인 원칙**
- 콘텐츠가 주인공이다. UI 장식보다 작업물과 메시지를 우선한다.
- 위계는 크기와 간격으로 만든다. 모든 요소를 카드나 박스로 감싸지 않는다.
- 정렬은 의도적이어야 한다. 비대칭 레이아웃도 그리드와 기준선에 맞춘다.
- 강조 색은 제한적으로 사용한다. 강조 색은 링크, CTA, 선택 상태 등 의미가 있을 때만 쓴다.
- 애니메이션은 사용성을 방해하지 않는다. 움직임이 없어도 모든 핵심 정보와 기능에 접근할 수 있어야 한다.

### 2. 컬러 시스템

기본은 따뜻한 흰색과 잉크에 가까운 검정의 고대비 조합이다. 아래 값은 시작점이며, 실제 브랜드 컬러가 있다면 접근성 검토 후 대체한다.

| 토큰 | 값 | 사용 |
|---|---|---|
| `color-canvas` | `#FFFFFF` | 기본 배경 |
| `color-surface-subtle` | `#F5F5F3` | 보조 영역, 입력 배경 |
| `color-ink` | `#202020` | 제목, 본문 |
| `color-ink-muted` | `#686868` | 보조 설명, 메타데이터 |
| `color-line` | `#D9D9D6` | 구분선, 입력 테두리 |
| `color-accent` | `#F2552C` | 주요 CTA, 핵심 링크 |
| `color-accent-hover` | `#D94320` | CTA 호버 상태 |
| `color-focus` | `#245DDA` | 키보드 포커스 표시 |
| `color-success` | `#267447` | 성공 상태 |
| `color-error` | `#B42318` | 오류 상태 |

**사용 규칙**
- 한 화면에서 주요 강조 색은 원칙적으로 1개만 사용한다.
- 강조 색을 넓은 배경 면적으로 남용하지 않는다.
- 일반 텍스트는 배경과 충분한 대비를 확보한다. 일반 텍스트 대비비는 WCAG 기준 4.5:1 이상을 목표로 한다.
- 색만으로 상태를 구분하지 않는다. 아이콘, 레이블, 텍스트를 함께 제공한다.
- 얇은 선과 비활성 텍스트도 실제 화면에서 식별 가능한지 확인한다.

### 3. 타이포그래피

**폰트 방향**
- 제목: 개성이 과하지 않은 산세리프 계열
- 본문/UI: 가독성이 좋은 시스템 산세리프
- 장식용 폰트: 브랜드 컨셉상 꼭 필요한 경우에만 제한적으로 사용

권장 폰트 스택:

```css
font-family: Inter, "Helvetica Neue", Arial, "Noto Sans KR",
  "Apple SD Gothic Neo", sans-serif;
```

| 토큰 | 데스크톱 | 모바일 | 굵기 | 줄 높이 | 용도 |
|---|---:|---:|---:|---:|---|
| `type-display` | 72–104px | 44–60px | 400–500 | 0.95–1.05 | 히어로 제목 |
| `type-h1` | 56–72px | 36–48px | 400–500 | 1.05–1.15 | 페이지 제목 |
| `type-h2` | 36–48px | 28–36px | 400–500 | 1.1–1.2 | 섹션 제목 |
| `type-h3` | 24–32px | 22–28px | 500 | 1.2–1.3 | 하위 제목 |
| `type-body-lg` | 18–20px | 17–19px | 400 | 1.5–1.65 | 리드 문단 |
| `type-body` | 16px | 16px | 400 | 1.5–1.7 | 기본 본문 |
| `type-label` | 13–14px | 13–14px | 500 | 1.4 | 버튼, 라벨 |
| `type-caption` | 12–13px | 12–13px | 400 | 1.4–1.5 | 이미지 캡션, 메타 |

**타이포그래피 규칙**
- 한 화면에서 서체 종류는 2개 이하로 유지한다.
- 큰 제목은 짧고 명확하게 쓴다. 문장이 길면 줄바꿈 위치를 직접 검토한다.
- 본문 한 줄 길이는 대략 45–80자 범위에서 읽기 좋게 조정한다.
- 한글 제목에 과도한 자간 축소를 적용하지 않는다.
- 모든 대문자 스타일은 짧은 영문 라벨에만 사용한다.
- 본문과 캡션을 지나치게 작게 만들어 여백을 확보하지 않는다.

### 4. 레이아웃과 그리드

**기준**
- 기준 간격 단위: 4px
- 데스크톱 최대 콘텐츠 폭: 1280px
- 데스크톱 그리드: 12컬럼
- 태블릿 그리드: 8컬럼
- 모바일 그리드: 4컬럼
- 데스크톱 거터: 20–28px
- 모바일 좌우 여백: 20–24px

| 토큰 | 값 | 대표 사용 |
|---|---:|---|
| `space-1` | 4px | 아이콘과 텍스트 |
| `space-2` | 8px | 작은 내부 간격 |
| `space-3` | 12px | 라벨 그룹 |
| `space-4` | 16px | 기본 컴포넌트 간격 |
| `space-6` | 24px | 카드·폼 내부 |
| `space-8` | 32px | 작은 섹션 간격 |
| `space-12` | 48px | 제목과 콘텐츠 |
| `space-16` | 64px | 섹션 내부 여백 |
| `space-24` | 96px | 큰 섹션 간격 |
| `space-32` | 128px | 히어로·대형 전환 구간 |

**레이아웃 규칙**
- 모든 콘텐츠를 화면 중앙에 고정하지 말고, 프로젝트 성격에 맞춰 좌측 정렬과 비대칭 배치를 활용한다.
- 섹션 사이 간격은 내부 요소 사이 간격보다 확실히 크게 둔다.
- 한 페이지 안에서 정렬 기준선을 반복해 시각적 일관성을 만든다.
- 이미지 갤러리는 동일한 비율을 반복하거나, 비대칭을 쓰더라도 규칙을 유지한다.
- 넓은 화면에서도 본문이 지나치게 길게 늘어나지 않도록 최대 폭을 제한한다.

### 5. 이미지와 미디어

**이미지 사용**
- 이미지가 프로젝트의 핵심이면 충분한 크기로 노출한다.
- 이미지마다 동일한 프레임을 강제하기보다 콘텐츠 특성에 맞는 비율을 선택한다.
- 썸네일은 같은 목록 안에서 크롭 방식과 비율을 일관되게 유지한다.
- 이미지 아래에는 필요한 경우 프로젝트명, 역할, 연도 등 짧은 메타데이터를 배치한다.
- 이미지에 텍스트를 직접 합성하는 방식은 반응형과 접근성을 고려해 최소화한다.

**권장 비율**
- 히어로/프로젝트 대표 이미지: `16:9` 또는 원본 비율
- 프로젝트 카드: `4:3`, `3:2`
- 세로 작업물/포스터: `3:4` 또는 `4:5`
- 아트 디렉션용 대형 이미지: 콘텐츠에 따라 자유 비율

**이미지 접근성**
- 의미 있는 이미지에는 내용을 설명하는 대체 텍스트를 제공한다.
- 장식 이미지에는 빈 대체 텍스트(`alt=""`)를 사용한다.
- 이미지 안의 중요한 정보를 텍스트로도 제공한다.
- 로딩 지연 시 레이아웃이 튀지 않도록 이미지 비율 또는 크기를 미리 지정한다.

### 6. 컴포넌트 가이드

**버튼**
- Primary: 배경 `color-accent`, 텍스트 흰색, 높이 44–48px, 좌우 패딩 18–24px, 모서리 4–999px 중 하나를 선택해 일관되게 적용, 호버 시 배경색 또는 밝기를 조금 변경한다.
- Secondary: 투명 또는 `color-surface-subtle` 배경, 1px `color-line` 테두리, `color-ink` 텍스트.
- Text button: 배경과 테두리 없이 텍스트와 작은 화살표로 표현할 수 있다. 링크처럼 보이는 요소는 실제 클릭 동작을 제공한다.
- 주요 CTA는 한 화면에서 가장 눈에 띄는 액션으로 제한한다.
- 버튼 높이는 터치 환경에서 최소 44px를 권장한다.
- 기본, 호버, 포커스, 눌림, 비활성 상태를 모두 정의한다.

**링크**
- 본문 링크는 주변 텍스트와 구별 가능해야 한다.
- 색상만으로 구분하지 말고 밑줄 또는 명확한 호버/포커스 표시를 제공한다.
- 외부 링크는 새 창 여부와 이동 목적을 예측할 수 있게 한다.

**입력 필드**
- 높이: 44–52px
- 기본 배경: 흰색 또는 `color-surface-subtle`
- 테두리: 1px `color-line`
- 라벨은 필드 바깥에 배치한다.
- 오류는 필드 근처에 원인과 해결 방법을 텍스트로 안내한다.
- 플레이스홀더를 라벨의 대체물로 사용하지 않는다.

**프로젝트 카드**
- 그림자와 둥근 모서리를 기본값으로 사용하지 않는다.
- 이미지, 제목, 역할/분류, 연도 순으로 정보 우선순위를 정한다.
- 카드 전체가 링크라면 키보드로도 접근할 수 있어야 한다.
- 호버 시 이미지 확대는 최대한 절제하고, 텍스트 가독성을 해치지 않는다.

**구분선**
- `1px solid color-line`을 기본으로 한다.
- 모든 요소에 테두리를 두르기보다 섹션 구분이나 목록의 리듬을 만들 때 사용한다.

**내비게이션**
- 항목 수를 최소화한다.
- 로고/이름, 핵심 메뉴, 연락 또는 주요 CTA로 구조를 단순화한다.
- 스크롤 시 고정 헤더가 콘텐츠를 과도하게 가리지 않는지 확인한다.
- 현재 위치는 색, 밑줄, 굵기 등으로 분명히 표현한다.

### 7. 페이지 구성 패턴

**포트폴리오 홈**
- 상단 내비게이션
- 큰 타이포그래피 중심의 인트로
- 대표 프로젝트 또는 이미지 갤러리
- 간단한 소개/전문 분야
- 연락 CTA
- 최소한의 푸터

**프로젝트 상세**
- 프로젝트명, 연도, 역할
- 대표 이미지
- 프로젝트 개요
- 과정 및 주요 산출물
- 상세 이미지/설명
- 이전·다음 프로젝트 링크
- 연락 또는 목록으로 돌아가기

**서비스/스튜디오 랜딩 페이지**
- 한 문장으로 가치 제안
- 대표 작업물
- 서비스 또는 전문 분야
- 사례 및 성과
- 작업 방식
- 연락 CTA

각 페이지는 섹션을 많이 넣는 것보다 사용자의 핵심 질문에 빠르게 답하는 것을 우선한다.

### 8. 인터랙션과 모션

| 항목 | 권장 값 | 사용 |
|---|---|---|
| 빠른 상태 변화 | 120–180ms | 버튼, 링크 |
| 기본 전환 | 180–260ms | 색상, 투명도 |
| 큰 영역 전환 | 300–450ms | 메뉴, 모달 |
| 이징 | `cubic-bezier(0.2, 0, 0, 1)` | 기본 전환 |

**원칙**
- 호버 효과는 색상, 밑줄, 투명도, 작은 이동 정도로 제한한다.
- 스크롤 애니메이션은 콘텐츠를 읽는 흐름보다 앞서지 않게 한다.
- 핵심 콘텐츠를 애니메이션 완료 전까지 숨기지 않는다.
- 키보드 포커스 상태를 호버 상태와 별도로 설계한다.
- `prefers-reduced-motion: reduce` 설정을 지원한다.
- 자동 재생 영상은 음소거와 정지 제어를 제공하고, 필요 이상으로 반복하지 않는다.

### 9. 반응형 기준

| 구간 | 화면 폭 | 기준 |
|---|---|---|
| Mobile | 0–767px | 4컬럼, 단일 열 우선 |
| Tablet | 768–1023px | 8컬럼, 2열 구성 검토 |
| Desktop | 1024–1439px | 12컬럼, 넉넉한 외부 여백 |
| Wide | 1440px 이상 | 콘텐츠 최대 폭 제한, 여백 확장 |

**반응형 체크**
- 큰 제목은 화면 폭에 따라 유동적으로 축소한다.
- 데스크톱의 다열 갤러리는 모바일에서 단일 열 또는 간결한 2열로 전환한다.
- 가로 스크롤은 의도된 갤러리 경험이 아니라면 피한다.
- 메뉴, 버튼, 링크의 터치 영역을 충분히 확보한다.
- 이미지 크롭이 핵심 피사체를 잘라내지 않는지 각 화면에서 확인한다.

예시:

```css
.page-shell {
  width: min(100% - 48px, 1280px);
  margin-inline: auto;
}

.hero-title {
  font-size: clamp(2.75rem, 7vw, 6.5rem);
  line-height: 0.98;
  letter-spacing: -0.04em;
}

.section {
  padding-block: clamp(4rem, 10vw, 8rem);
}

@media (max-width: 767px) {
  .page-shell {
    width: calc(100% - 40px);
  }
}
```

### 10. 접근성과 사용성

- 본문 텍스트 대비비는 WCAG AA 기준을 목표로 한다.
- 모든 인터랙티브 요소는 키보드로 사용할 수 있어야 한다.
- 포커스 표시를 제거하지 않는다.
- 제목 태그는 시각적 크기와 별개로 문서 구조에 맞게 사용한다.
- 이미지 대체 텍스트, 폼 라벨, 오류 안내를 제공한다.
- 링크와 버튼은 목적에 맞게 구분한다. 페이지 이동은 링크, 동작 실행은 버튼을 사용한다.
- 확대/축소와 작은 화면에서도 콘텐츠가 잘리지 않도록 한다.
- 움직임 감소 설정을 존중한다.

### 11. 콘텐츠 작성 톤

- 제목은 짧고 구체적으로 쓴다.
- 소개 문구는 추상적인 수식어보다 작업의 목적과 가치를 설명한다.
- 버튼 레이블은 "더 알아보기"보다 "프로젝트 보기", "문의하기"처럼 행동을 명확히 표현한다.
- 프로젝트 설명은 문제 → 접근 방식 → 결과 순서로 정리한다.
- 메타데이터는 같은 순서와 형식으로 반복한다.

### 13. 디자인 QA 체크리스트

**시각적 일관성**
- [ ] 컬러 토큰 외의 임의 색상을 무분별하게 추가하지 않았는가?
- [ ] 제목, 본문, 캡션의 위계가 명확한가?
- [ ] 여백과 정렬 기준이 페이지 전체에서 일관적인가?
- [ ] 이미지 비율과 캡션 형식이 목록 안에서 통일되어 있는가?
- [ ] 장식용 카드, 그림자, 테두리를 불필요하게 사용하지 않았는가?

**인터랙션**
- [ ] 버튼과 링크의 역할이 분명한가?
- [ ] 호버, 포커스, 눌림, 비활성 상태가 정의되어 있는가?
- [ ] 키보드만으로 주요 기능을 이용할 수 있는가?
- [ ] 모션 감소 설정에서도 콘텐츠가 정상적으로 보이는가?

**반응형·접근성**
- [ ] 모바일에서 가로 스크롤이 의도치 않게 생기지 않는가?
- [ ] 텍스트가 확대되어도 잘리거나 겹치지 않는가?
- [ ] 색상 대비가 충분한가?

- [ ] 터치 대상이 충분히 큰가?

**최종 검수**
- [ ] 첫 화면에서 사이트의 목적이 빠르게 이해되는가?
- [ ] 가장 중요한 콘텐츠가 시각적으로 우선하는가?

- [ ] 실제 콘텐츠를 넣었을 때도 레이아웃이 자연스러운가?

### 14. 최종 원칙

여백으로 구조를 만들고, 타이포그래피로 위계를 세우며, 이미지로 개성을 전달한다. 미니멀 디자인은 요소를 무조건 줄이는 것이 아니라, 각 요소가 존재해야 하는 이유를 분명하게 만드는 작업이다.

## 반영 내용

- 기본 이력서 페이지를 새로 구성하고, 따뜻한 흰색 바탕·잉크색 타이포그래피·제한적인 강조색·얇은 구분선 중심의 외부 스타일시트를 적용했다.
- 데스크톱 그리드와 좁은 화면의 단일 열 배치, 키보드 포커스, 모션 감소 설정을 반영했다.
- 실제 제공된 프로필 자료를 사용하고, 확인되는 실습 페이지에만 링크했다.
- 확인: 브라우저에서 데스크톱(1280px)과 모바일(375px) 레이아웃을 확인했고, 두 크기 모두 가로 넘침이 없다. 로컬 앵커와 실습 링크가 유효하며, 스타일시트가 연결되어 있다.

## 후속 확인

- F-05에서 실습 진행으로 기재된 3·5·6·7주차의 실습 페이지는 저장소에서 확인되지 않아 연결하지 않았다. 실제 페이지가 준비되면 링크를 추가한다.
- 실습 진행으로 기록된 3·5·6·7주차는 실제 페이지 파일이 없어 링크하지 않았다. 해당 주차 페이지가 준비되면 연결이 필요하다.
- 배포 URL과 W3C 검사기는 아직 확인하지 않았다.
